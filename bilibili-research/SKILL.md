# B站搜索词调研

对种子关键词进行B站搜索调研，分析搜索热度和竞争度，输出结构化选题池文档。

## 输入

通过参数接收种子关键词，格式灵活：
- 逗号分隔：`Claude Code, AI写代码, vibe coding`
- 换行分隔（多行输入）
- 或直接在对话中提供

如果用户没有提供关键词，先问用户要。给出示例帮助用户思考：
"请提供你想调研的种子关键词。比如你的内容定位相关的工具名、技术概念、痛点描述。示例：Claude Code, AI写代码, vibe coding, AI编程 翻车"

## 调研流程

对每个种子关键词，按顺序执行以下步骤。一次调研建议控制在 5-10 个种子词以内，避免搜索过于频繁。

### Phase 1: 扩展搜索

对每个种子词，用 **WebFetch 抓取 B站搜索结果页面**，可以获取完整的结构化数据（播放量、UP主、时长、URL）。

**核心方法 — WebFetch B站搜索页：**

对每个种子词，做 2 次 WebFetch：

**搜索 1 — 综合排序（默认热度）：**
```
WebFetch:
  url: https://search.bilibili.com/all?keyword={URL编码的种子词}&order=totalrank
  prompt: 从这个B站搜索结果页面中，提取所有视频的信息。对每个视频，提取：1. 视频标题（去除HTML标签） 2. 播放量（保留原始格式如"71.1万"） 3. UP主名称 4. 发布时间 5. 视频时长 6. 视频完整链接URL（https://www.bilibili.com/video/BVxxx 格式）。以markdown表格返回。
```

**搜索 2 — 最新发布（竞争度信号）：**
```
WebFetch:
  url: https://search.bilibili.com/all?keyword={URL编码的种子词}&order=pubdate
  prompt: 同上
```

关键词需要 URL 编码（中文字符用 %XX 格式）。可以用 Agent 并行执行多个种子词的搜索来加速。

**补充搜索（可选，用于关联词扩展）：**
```
WebSearch: "{种子词} 教程 bilibili"
```
WebSearch 用于发现 B站 站外的关联内容和长尾关键词，作为 WebFetch 数据的补充。

**从 WebFetch 结果中可获取的字段：**
- 视频标题（完整）
- 播放量（精确数字，如"71.1万"、"5451"）
- UP主名称
- 发布时间
- 视频时长
- 视频 URL（完整的 bilibili.com/video/BVxxx 链接）

大部分字段都能获取。偶尔某些字段缺失时标记为"—"。

### Phase 2: 数据整理

对每个种子词，将两次搜索（综合排序 + 最新发布）的结果合并去重，整理成表格：

```markdown
### 关键词: {种子词}

**热门视频（按综合排序）：**

| # | 标题 | 播放量 | UP主 | 发布时间 | 时长 | URL |
|---|------|--------|------|---------|------|-----|
| 1 | ... | 71.1万 | xxx | 01-25 | 44:45 | https://www.bilibili.com/video/BVxxx |
| 2 | ... | ... | ... | ... | ... | ... |

**近期视频（按发布时间）：**

| # | 标题 | 播放量 | UP主 | 发布时间 | 时长 | URL |
|---|------|--------|------|---------|------|-----|
| 1 | ... | ... | ... | 03-28 | ... | https://www.bilibili.com/video/BVxxx |
```

### Phase 3: 分析判断

对每个关键词，基于搜索结果分析以下维度：

**搜索热度（基于搜索结果中视频的播放量）：**
- 高：搜索结果中多条视频播放量 > 5万
- 中：搜索结果中多条视频播放量在 1万-5万
- 低：搜索结果中视频播放量普遍 < 1万
- 无法判断：播放量数据不足

**竞争度（基于近期内容密度）：**
- 高：搜索结果中近30天有 > 5条新视频
- 中：搜索结果中近30天有 2-5 条新视频
- 低：搜索结果中近30天 < 2 条新视频
- 无法判断：时间数据不足

**蓝海信号：**
- 是否存在低粉UP主的高播放视频（说明选题自带流量）
- 是否搜索结果较少（说明内容供给不足）

**高价值标题词：**
- 统计搜索结果标题中频繁出现的词汇

### Phase 4: 2x2 矩阵分类

将所有关键词分为四类：

```
                 搜索量高                搜索量低
            ┌──────────────────┬──────────────────┐
竞争少      │  ★ 金矿           │  补充选题         │
            │  优先做            │  可做，流量小     │
            ├──────────────────┼──────────────────┤
竞争多      │  需要差异化        │  不做             │
            │  找独特切入点      │                  │
            └──────────────────┴──────────────────┘
```

对于"需要差异化"的关键词，主动建议差异化角度：
- 对比实验（"同一个需求，两种方式"）
- 翻车+解法（"X个坑，以及怎么解决"）
- 特定语言/框架（缩小范围降低竞争）
- 方法论层（大多数人讲"怎么用"，你讲"为什么"）

## 执行注意事项

- 每个种子词做 2 次 WebFetch（综合排序 + 最新发布），5-10 个种子词意味着 10-20 次 WebFetch。可以分批并行执行（每批2-3个种子词的 WebFetch 同时发出）。
- WebFetch 抓 B站搜索页通常能获取播放量、UP主、时长、URL 等完整数据。偶尔缺失时标记"—"，不要编造数据。
- 关键词需要 URL 编码。中文关键词示例：`AI写代码` → `AI%E5%86%99%E4%BB%A3%E7%A0%81`。英文关键词可直接用 `+` 连接空格：`Claude+Code`。
- WebFetch 的 prompt 要明确要求"以markdown表格返回"，并要求提取所有视频字段（标题、播放量、UP主、发布时间、时长、URL）。
- B站搜索结果页默认只显示约 10-20 条视频。如需更多数据，可以 WebFetch 第 2 页：在 URL 后加 `&page=2`。
- 输出文件写入后，告诉用户文件路径。WebFetch 数据已经比较完整，但仍建议对"金矿"类选题在B站手动验证（搜索结果排序可能有差异）。
